# Push-уведомления Android

Реализованы уведомления о новых текстовых сообщениях, изображениях и видео в личных и групповых чатах. Нажатие открывает чат; если он уже открыт на экране телефона, уведомление не показывается. В Firebase передаются идентификаторы чата, сообщения и получателя, а также случайная привязка установки, но не текст, имя отправителя или вложения. На телефоне отображается «Messenger — New message».

## 1. Создать проект Firebase

1. Откройте [Firebase Console](https://console.firebase.google.com/) и создайте проект. Google Analytics для этой реализации не требуется.
2. Добавьте Android-приложение с package name **com.monoreaz.messenger**.
3. Скачайте `google-services.json` и сохраните в `android/app/google-services.json`.
4. В Project settings → Cloud Messaging проверьте, что Firebase Cloud Messaging API (V1) включён.
5. В Project settings → Service accounts создайте JSON-ключ сервисного аккаунта. Сохраните его на сервере как `secrets/firebase-service-account.json` в корне репозитория. Не отправляйте этот файл в чат и не добавляйте в Git. Ограничьте права чтения файла владельцем (`chmod 600`). Для существующего сервисного аккаунта нужны права отправки FCM в этом проекте.

Оба файла относятся к **одному проекту Firebase**. Каталог `secrets/` и Android-конфигурация исключены из Git. Серверный ключ нельзя помещать в APK, frontend или GitHub-переменную для Android-конфигурации.

## 2. Включить сервер

В `.env` установите:

```dotenv
PUSH_ENABLED=true
```

Из корня проекта:

```sh
docker compose build backend
docker compose run --rm --no-deps backend alembic upgrade head
docker compose up -d backend
```

Compose монтирует `secrets/` только для чтения и задаёт `GOOGLE_APPLICATION_CREDENTIALS`. Серверу нужен исходящий HTTPS-доступ к Google. Входящий доступ из Google к домашнему серверу не требуется.

Если frontend развёрнут как статическая сборка, также пересоберите и опубликуйте её. В текущем Compose Vite читает исходники с диска.

## 3. Собрать и установить APK

Локально выполните из `android/`:

```sh
gradle :app:assembleDebug :app:lintDebug
```

Для GitHub Actions добавьте repository secret **ANDROID_GOOGLE_SERVICES_JSON**, содержащий полный JSON из `google-services.json`, затем запустите workflow Android APK. Сборка без этого файла остаётся рабочей, но push в ней выключен; CI выдаст предупреждение.

Установите новый APK, войдите в аккаунт и разрешите уведомления. На Android 13+ разрешение запрашивается после входа. Если отказали, откройте ⚙ → Notifications и разрешите уведомления в настройках Android. Для работы FCM нужны Google Play services и доступ к интернету. Приложение можно устанавливать APK-файлом без публикации в Google Play.

## 4. Проверить на телефоне

1. Войдите на телефоне как пользователь A. Для долгой сессии используйте Remember me.
2. Сверните приложение и с другого аккаунта B отправьте A текст, изображение и видео. Проверьте личный чат и группу.
3. Должно появиться уведомление со звуком, если системные настройки его разрешают. Нажмите его — откроется соответствующий чат.
4. Откройте этот чат на телефоне и отправьте ещё сообщение: дополнительного системного уведомления быть не должно.
5. Заблокируйте экран и повторите. Также проверьте после удаления приложения из списка недавних.
6. Выйдите из аккаунта A: существующие уведомления очищаются, новые для A не показываются. Войдите как B и проверьте отсутствие уведомлений аккаунта A.
7. Отзовите сессию телефона с другого устройства: сервер больше не должен отправлять push этой сессии. Блокировка аккаунта также прекращает отправку.

Tailscale нужен, чтобы открыть чат на нашем сервере; доставка FCM использует интернет-соединение телефона. Принудительная остановка приложения в системных настройках Android останавливает уведомления до следующего запуска. Настройки энергосбережения производителя также могут влиять на доставку.

## Поведение и ограничения

- Регистрация устройства требует access token и действующую refresh-cookie того же пользователя. Привязка следует за сессией, поэтому выход, отзыв, срок действия и блокировка учитываются на сервере.
- Android проверяет случайную привязку получателя перед показом: задержанные push прежнего аккаунта или сервера игнорируются.
- Токен обновляется при открытом приложении, возобновлении, смене access token и повторной попытке раз в минуту. Если FCM заменил токен, пока приложение закрыто, регистрация восстановится при следующем открытии.
- Отправка выполняется фоновой задачей после сохранения сообщения. Ошибки FCM не отменяют сообщение; недействительные FCM-токены удаляются. Очередь не сохраняется между рестартами сервера, автоматической повторной доставки после сбоя FCM пока нет. Сообщения остаются в истории чата.
- Сигнал хранится в FCM до одного часа; уже отправленный сигнал может прийти после чтения сообщения на другом устройстве. Уведомления одного чата заменяют друг друга.
- Фоновые входящие звонки, iOS и браузерные push в эту реализацию не входят.

Документация: [Android FCM](https://firebase.google.com/docs/cloud-messaging/android/get-started), [приём сообщений](https://firebase.google.com/docs/cloud-messaging/android/receive-messages), [Firebase Admin](https://firebase.google.com/docs/admin/setup).
